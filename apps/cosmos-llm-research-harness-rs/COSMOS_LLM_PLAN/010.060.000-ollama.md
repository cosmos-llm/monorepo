# 010.060 — Ollama provider

Local models. Valuable for the research harness specifically: no API key, no
per-query cost, and no data leaving the machine — which matters for researchers
working with unpublished or confidential material.

## Microsteps

### 010.060.010 — Two possible routes

Ollama exposes both a native API (`/api/chat`, `/api/generate`) and an
OpenAI-compatible one (`/v1/chat/completions`).

The compatible endpoint means `Client::new_with_base_url("openai", "", "http://localhost:11434/v1")`
mostly works today. Document that as the quick path.

A native provider is still worth building for what the compatible endpoint does not
expose: `/api/tags` for locally-installed models, `/api/pull` progress, `keep_alive`,
and Ollama-specific options. Do the native one.

### 010.060.020 — No API key

Auth is absent. The provider must not require a key, and `Config` must not treat a
missing key as an error for it. Check that the key-resolution path in
[010.020.010](010.020.000-provider-registry.md)'s `env_keys` handles an empty list.

`OLLAMA_HOST` for the base URL, defaulting to `http://localhost:11434`.

### 010.060.030 — Connection failures are the common case

Ollama is usually not running. The error must say so plainly — "cannot reach Ollama
at http://localhost:11434; is it running? (`ollama serve`)" — rather than surfacing
a raw connection-refused.

This is the single most-hit error path of any provider here, and a good message
saves a support conversation every time.

### 010.060.040 — Model availability

`/api/tags` lists installed models. A request for a model that is not pulled fails
with a message naming the `ollama pull` command that would fix it.

`models()` returns what is actually installed, not a catalog — which is more useful
than any hosted provider's list, and worth noting in docs.

### 010.060.050 — Capabilities vary by model

Tool support depends on the model, not on Ollama. Llama 3.1 supports tools; many
models do not. `ModelInfo` should reflect this where `/api/show` reports it.

### 010.060.060 — Timeouts are different here

A local model on CPU can take minutes for a first token, especially while loading
weights into memory. The default HTTP timeout that suits a hosted API will abort
these. Longer default for this provider, configurable, and documented.

## Verification

- Tests against a mocked Ollama HTTP surface.
- Connection-refused produces the helpful message.
- Missing model names the `ollama pull` command.
- No API key required anywhere in the path.
