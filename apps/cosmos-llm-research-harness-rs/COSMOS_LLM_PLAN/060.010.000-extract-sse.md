# 060.010 — Extract `sse-decode`

`cosmos-llm/src/sse.rs` implements a server-sent events decoder. SSE is a W3C
standard used far beyond LLM APIs — progress feeds, live dashboards, webhooks.
Nothing in the decoder is LLM-specific.

## What is already right

The existing implementation handles the things a naive decoder gets wrong:

- Buffers across packet boundaries, so an event split by TCP is still parsed as one.
- Recovers a final event that arrived without its terminating blank line
  (`SseDecoder::finish`), which real servers do on abrupt close.
- Recognizes the `[DONE]` sentinel.

That is a good decoder. Extracting it makes it available to people who need one and
would otherwise write a worse one.

## Microsteps

### 060.010.010 — Move verbatim

New crate `sse-decode`. `cosmos-llm` depends on it. Existing tests move with it and
pass unchanged.

### 060.010.020 — Complete the spec

Standard SSE has fields the current decoder may not handle, since it only ever
faced LLM APIs:

- `event:` — named event types.
- `id:` — last-event-ID for reconnection.
- `retry:` — server-suggested reconnect delay.
- `:` — comment lines, ignored (used as keepalives).
- Multiple `data:` lines in one event, joined with newlines.

Add what is missing. A crate published as an SSE decoder should decode SSE, not
the subset three vendors happen to send.

### 060.010.030 — `[DONE]` is not part of SSE

`is_done()` checks for OpenAI's `[DONE]` sentinel, which is a convention of that
API, not part of the standard.

Keep it as an opt-in helper (`SseEvent::is_data_sentinel("[DONE]")` or a feature),
not as core behavior. A generic decoder should not treat one vendor's magic string
as special.

### 060.010.040 — Byte and line limits

A malicious or broken server can send an event that never terminates. Configurable
maximum event size and line length, erroring rather than growing a buffer without
bound.

This matters more once the crate is used against arbitrary servers rather than
three known APIs.

### 060.010.050 — README and docs

Full rustdoc, doctests per the crate checklist, and a README opening with what SSE
is and why this decoder handles the hard cases. No mention of LLMs needed, which is
the test from [060](060.000.000-phase-extraction.md).

## Verification

- `cosmos-llm`'s streaming tests pass unchanged after extraction.
- Conformance tests against the SSE specification's examples.
- Split-packet, missing-final-newline, comment, and multi-`data` cases covered.
- Oversized event errors rather than allocating without bound.
- No `cosmos-llm` dependency; builds standalone.
