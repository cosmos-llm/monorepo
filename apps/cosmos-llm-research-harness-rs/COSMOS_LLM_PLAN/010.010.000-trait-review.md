# 010.010 — `Provider` trait review

Do this before adding providers four through sixteen. Changing a trait with three
implementors is an afternoon; with fourteen it is a project.

## Microsteps

### 010.010.010 — Lifetime asymmetry

`completion<'a>(&'a self, req: &'a CompletionRequest)` returns a future borrowing
`'a`, while `stream_completion` returns a `'static` `CompletionStream`. The
asymmetry means a caller can spawn a stream onto a task but not a completion.

Options: take `req` by value, or by `Arc<CompletionRequest>`. `Arc` avoids cloning
a large message list per retry attempt, which matters once
[030.010](030.010.000-retry.md) exists and the same request is sent three times.

Recommendation: `Arc<CompletionRequest>`, both methods `'static`.

### 010.010.020 — Embeddings

Ruby's `Providers::Base` defines `completion`, `models`, `stream`, `embedding`, and
`handle_response`; `Client` exposes `embed`. Rust has no embeddings. Every
RAG-shaped consumer needs them, and the research harness will want them for source
similarity and deduplication.

Add now, as an optional trait method returning an unsupported error by default,
with a `supports_embeddings()` companion mirroring how streaming is handled. That
pattern already exists in the trait and works.

Match Ruby's names: `Provider::embedding`, `Client::embed`
([005](005.000.000-ruby-parity-principle.md)).

### 010.010.025 — Fluent client builders (Ruby gap)

Ruby's `Client` has nine builders: `with_provider`, `with_model`,
`with_temperature`, `with_max_tokens`, `with_tools`, `with_tool_choice`,
`with_system`, `with_top_p`, `with_stop`, plus `clone_with`.

Rust has three: `with_model`, `with_provider`, `with_provider_at`. A Rust caller
sets temperature on the `CompletionRequest`; a Ruby caller sets it on the client.
The same program written in both languages does not look the same, which is the
divergence [005](005.000.000-ruby-parity-principle.md) exists to prevent.

Add the six missing builders as per-client defaults that an explicit
`CompletionRequest` field overrides. Same names as Ruby. `clone_with` becomes
Rust's ordinary `Clone` plus a builder call, so it needs no direct equivalent.

Ruby's builders return a cloned client; Rust's take `mut self` and return `Self`.
Same ergonomics, different ownership — an allowed difference.

### 010.010.030 — Capability reporting, generalized

`supports_streaming()` is one boolean. There will be more: embeddings, tools,
vision, JSON mode, system messages (some providers do not take them),
prompt caching.

A single `capabilities() -> Capabilities` struct scales better than a boolean per
feature. Keep `supports_streaming()` as a deprecated shim so this is not a
breaking change. See [010.030](010.030.000-capabilities.md).

### 010.010.040 — Model metadata

`models()` returns `Vec<String>`. Consumers need more: context window (for
trimming), pricing (for cost), and capability flags per model — a provider can
offer both vision and non-vision models.

Add `model_info(&str) -> Option<ModelInfo>` alongside. Keep `models()` for the
simple case.

Note Anthropic's list is static in the current implementation. Static is fine and
honest; `ModelInfo` for a static list is easy to keep accurate.

### 010.010.050 — Request cancellation

Long completions need to be abortable. `reqwest` cancels on future drop, so this
mostly works already — but confirm it, and document it. The harness's
cancellation story ([`../PLAN/030.030.060`](../PLAN/030.030.000-agent-loop.md))
depends on drop actually closing the connection rather than leaking a task.

### 010.010.060 — Then freeze it

Once these land, the trait should be stable enough to add a dozen implementations
against. Any further change costs fourteen edits, so make the case in writing
before proposing one.

## Verification

- All three existing providers migrate with no behavior change (their test suites
  pass unmodified except for signatures).
- A no-op provider implementing only the required methods compiles, confirming the
  defaults are genuinely optional.
