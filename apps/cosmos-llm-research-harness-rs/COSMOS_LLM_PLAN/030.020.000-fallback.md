# 030.020 — Provider fallback chains

## Microsteps

### 030.020.010 — `FallbackChain`

An ordered list of (provider, model) pairs. On a retryable exhaustion of one, move
to the next. Wraps a set of clients rather than living inside `Client`, so a
consumer that wants one provider is not paying for chain machinery.

```rust
let chain = FallbackChain::new()
    .add("openrouter", "openai/gpt-4o-mini")
    .add("anthropic", "claude-sonnet-5")
    .add("openai", "gpt-4o");
```

### 030.020.020 — Only fall back on the right errors

Advance the chain on `RateLimit`, `ServerError`, `Transport` — conditions that are
about *this provider right now*.

Do not advance on `InvalidRequest`, `Auth`, `ContentFiltered`, or `ContextLength`.
A malformed request will be malformed at the next provider too; trying it three
more times wastes time and money and produces three identical errors.

`ContextLength` is worth a note: falling back to a provider with a larger window
would sometimes work, and it is tempting. Do not do it implicitly — the caller
asked for a model, and silently answering with a different one that costs 10× is
not a decision a library should make. Expose the error; let the caller decide.

### 030.020.030 — Report every attempt

Total failure returns an error carrying each provider's last error. The old
TypeScript logged a warning per provider and then failed generically, so the actual
cause scrolled past in a wall of warnings.

The harness surfaces all of them ([`../PLAN/030.010.040`](../PLAN/030.010.000-provider-layer.md)).

### 030.020.040 — Model equivalence is the caller's problem

A chain from GPT-4o to Haiku changes quality, cost, and behavior. The library
executes the chain the caller configured; it does not reason about equivalence.

Document this plainly. A user who put a cheap model second in their chain and got a
cheap answer during an outage should have been told that is what a chain does.

### 030.020.050 — Interaction with retry

Retry within a provider, then fall back — not the reverse. Otherwise a transient
blip moves every request off the primary provider.

Make the total budget explicit: `max_attempts` per provider times chain length is
the worst case, and a caller should be able to see that number before enabling it.

### 030.020.060 — Streaming fallback has a boundary

Once a stream has yielded content, falling back means discarding partial output and
restarting — usually wrong, and confusing if the user is watching text appear and
then vanish.

Fall back only on failures *before the first chunk*. After that, surface the error.
Document the boundary; it is a genuine limitation, not an oversight.

## Verification

- Chain advances on retryable errors, stops on non-retryable.
- Total failure carries every provider's error.
- Retry exhausts before fallback advances.
- A stream failing after the first chunk does not fall back.
