# 040.020 — Budget-aware assembly

## Microsteps

### 040.020.010 — Blocks declare priority

```rust
pub enum BlockPriority {
    /// Never dropped. System prompt, the current query.
    Required,
    /// Dropped last.
    High,
    /// Dropped when needed.
    Normal,
    /// Dropped first. Supplementary context.
    Low,
}
```

Trimming without priorities means dropping in insertion order, which drops the
system prompt or keeps stale history over the current question.

### 040.020.020 — `render_within(budget)`

```rust
pub fn render_within(&self, budget: TokenBudget, fmt: &Renderer)
    -> Result<Rendered, ContextError>;
```

Drops lowest-priority blocks until it fits. Returns what was dropped, so the caller
can tell the user — silent truncation is how a model "forgets" something the user
knows they provided, with no explanation available.

Fails if `Required` blocks alone exceed the budget. That is a real error the caller
must handle, not something to paper over.

### 040.020.030 — Within-block trimming

Some blocks trim internally rather than dropping wholesale. Conversation history
drops from the middle outward, keeping the earliest turns (which carry setup) and
the most recent (which carry the thread).

Model as a per-block strategy: `Drop`, `TrimMiddle`, `TrimTail`, `Summarize`.
`Summarize` needs a model call, so it is a later addition — but declaring the
strategy now means adding it does not change the API.

### 040.020.040 — Reserve output tokens

The budget is the context window minus expected output. A caller asking for 4,000
output tokens against a 128k window has 124k for context.

`TokenBudget::for_model(info).reserving(4000)` makes this explicit. Getting it
wrong produces a request that is accepted and then truncated mid-answer.

### 040.020.050 — Determinism

Same blocks, same budget, same result — every time. Trimming that varies run to run
makes prompt caching useless and bug reports irreproducible.

No time-dependent or hash-order-dependent decisions anywhere in the path.

## Verification

- Required blocks survive every budget above their own size.
- Over-budget required blocks produce a clear error.
- Dropped-block report matches what was actually removed.
- Determinism test: identical inputs, byte-identical output, across 100 runs.
