# 070.010 — `cosmos-llm-agent`

The reusable agentic loop. The most valuable crate in this plan, because every
agentic consumer needs it and today each one writes it.

## This is a port, not a new design

Ruby already has the loop: `Cosmos::Llm::Tool::Loop` in
`lib/ruby/cosmos-llm-ruby-tool/lib/cosmos/llm/tool/loop.rb`, 186 lines. Read it
before writing anything ([005](005.000.000-ruby-parity-principle.md)).

```ruby
Loop.run(client:, tools:, user:, system: nil, max_steps: 10, schema: :anthropic, &dispatch)
# => { text:, steps_taken: }
```

It normalizes tool calls into `ToolCall { id, name, input }`, dispatches through a
`Registry` keyed by tool name, appends results as content blocks, and repeats until
the model stops calling tools or `max_steps` is reached. An optional block overrides
registry dispatch.

Its own docs note it generalizes a loop "app-local code has reimplemented more than
once", naming `cosmos-llm-researcher`'s `#run_tool_loop`. That is the same lesson
this plan is built on — inherit the conclusion.

**Port the shape first**, matching names: `run`, `max_steps`, the normalized
`ToolCall`, registry-or-closure dispatch, a result carrying final text and turns
taken. Then extend.

## Where Rust extends Ruby

Four things the Ruby loop lacks, all needed by the harness:

| Extension | Why |
|---|---|
| Cancellation | The TUI must abort a run mid-call ([`../PLAN/030.030.060`](../PLAN/030.030.000-agent-loop.md)) |
| Event emission | Live progress, activity logging, test assertions |
| Permission dispatch | A research tool runs untrusted-ish tools ([`../PLAN/030.050`](../PLAN/030.050.000-permissions.md)) |
| Concurrent tool dispatch | Four independent searches should not be four round trips |

Also fix, in both languages: the Ruby loop builds Anthropic-format content-block
messages and explicitly does not support providers lacking
`tool_use?`/`tool_calls`/`text`. [020.020](020.020.000-tool-messages.md) is the
Rust fix; schedule the Ruby one alongside.

Every extension here gets scheduled back into the gem
([080.010](080.000.000-phase-ruby-parity.md)). Divergence is a recorded decision,
never drift.

## Scope

**In:** the tool-calling loop, turn limits, cancellation, event emission, agent
definitions, permission model and dispatch, concurrent tool execution, plan/build
modes.

**Out:** anything domain-specific (citations, methodology), anything about
persistence (a session store is an application's choice), anything about UI.

## Microsteps

### 070.010.010 — `Agent` and `AgentDefinition`

`AgentDefinition` as specified in
[`../PLAN/020.050`](../PLAN/020.050.000-agents.md), minus the research-specific
defaults. The six research agents ship in `cosmos-llm-research`, not here — this
crate defines the shape, not the instances.

### 070.010.020 — The loop

Ruby's `Loop.run` signature, translated. Takes a client (or a fallback chain), a
tool registry, an agent definition, and a message history. Returns a completed
exchange or an error.

Keep Ruby's names where they translate: `max_steps` stays `max_steps`, not
`turn_limit`. `ToolCall { id, name, input }` keeps those field names.
[`../PLAN/030.030.010`](../PLAN/030.030.000-agent-loop.md) says "turn limit" — read
that as `max_steps`.

Generic over the event sink, so a TUI, a log, and a test can each observe without
the loop knowing which.

### 070.010.030 — Permission model

From [`../PLAN/030.050`](../PLAN/030.050.000-permissions.md). The capability enum,
the resolution rules, and the single dispatch choke point.

The `Ask` case needs a callback — the crate cannot prompt, since it has no UI. A
`PermissionPrompt` trait the consumer implements, with a `DenyAll` default so a
non-interactive consumer is safe by construction rather than by remembering.

### 070.010.040 — Event sink

The event enum from [`../PLAN/030.030.070`](../PLAN/030.030.000-agent-loop.md) and
a `Sink` trait. Provide a no-op sink, a `tracing` sink, and a recording sink for
tests.

### 070.010.050 — State is the caller's

The loop does not persist anything. It takes a history and returns messages; where
those live is the application's business.

This is what keeps the crate usable by a server, a CLI, a TUI, and a test with no
argument about file formats. The harness's append-only store
([`../PLAN/020.030`](../PLAN/020.030.000-store.md)) is one implementation of a
concern this crate does not have.

### 070.010.060 — No async runtime opinion

Depend on `futures`, not on `tokio` directly, wherever possible. A consumer on
`async-std` or a custom runtime should not be excluded. Where a runtime primitive
is unavoidable (timeouts, semaphores), feature-gate the `tokio` implementation.

## Verification

- Full loop test against the mock provider with no other Cosmos crate beyond
  `cosmos-llm` and `cosmos-llm-tool`.
- A behavioral test mirroring Ruby's `Loop` spec, asserting the same outcomes for
  the same scripted exchange — the cross-language check that the port is faithful.
- Permission matrix tests with a scripted prompt implementation.
- The default `PermissionPrompt` denies.
- No dependency on anything research-specific.
- A trivial non-research agent (an echo bot with one tool) built in an example,
  proving the crate is not secretly research-shaped.
