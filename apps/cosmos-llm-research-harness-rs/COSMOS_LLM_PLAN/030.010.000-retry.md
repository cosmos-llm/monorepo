# 030.010 — Error classification and retry

## The problem underneath

`CosmosError` today cannot tell a caller whether retrying is sensible. An HTTP
error is `CosmosError::Http(reqwest::Error)` regardless of whether the status was
429 (retry after the given delay), 400 (never retry — the request is wrong), 500
(retry), or 401 (never retry — fix your key).

Every consumer that wants to retry has to reach into the error, and most will get
it wrong. Classification has to come first.

## Microsteps

### 030.010.010 — Adopt Ruby's error taxonomy

Ruby's `Cosmos::Llm::Errors` already defines the classification, in twelve classes
under a base `Error`. Port it rather than inventing one
([005](005.000.000-ruby-parity-principle.md)):

```rust
#[non_exhaustive]
pub enum CosmosError {
    /// Generic API failure. Ruby: APIError
    Api { provider: String, message: String },
    /// 429. Ruby: RateLimitError. Retryable; `retry_after` from the header.
    RateLimit { provider: String, retry_after: Option<Duration> },
    /// 401/403. Ruby: AuthenticationError. Never retryable.
    Authentication { provider: String, message: String },
    /// 400/422. Ruby: InvalidRequestError. Never retryable.
    InvalidRequest { provider: String, message: String, param: Option<String> },
    /// Ruby: ResourceNotFoundError.
    ResourceNotFound { provider: String, resource: String },
    /// Ruby: TimeoutError. Retryable.
    Timeout { provider: String, elapsed: Duration },
    /// 5xx. Ruby: ServerError. Retryable.
    Server { provider: String, status: u16 },
    /// Ruby: UnsupportedProviderError. (Already present as UnsupportedProvider.)
    UnsupportedProvider { name: String },
    /// Ruby: ConfigurationError.
    Configuration { message: String },
    /// Ruby: ModelNotFoundError. Distinct from ResourceNotFound — callers can
    /// suggest an alternative model.
    ModelNotFound { provider: String, model: String },
    /// Ruby: InsufficientQuotaError. Not retryable; retrying spends nothing but time.
    InsufficientQuota { provider: String },
    /// Ruby: InvalidResponseError. Response did not parse; it will not next time either.
    InvalidResponse { provider: String, message: String },
    /// Ruby: NetworkError. Connection resets, DNS. Retryable.
    Network { source: reqwest::Error },
    /// Ruby: StreamingError. (Already present as Streaming.)
    Streaming(String),

    // No Ruby equivalent yet — add to Ruby in phase 080.
    /// Content filter or safety block. Not retryable.
    ContentFiltered { provider: String, reason: String },
    /// Context length exceeded. Callers can trim and retry.
    ContextLength { provider: String, limit: Option<u32> },
}

impl CosmosError {
    pub fn is_retryable(&self) -> bool;
    pub fn retry_after(&self) -> Option<Duration>;
}
```

Ruby's set is broader than what I would have designed, and better for it.
`InsufficientQuota` and `ModelNotFound` are conditions a caller can act on
specifically — "top up your account" and "that model does not exist here" are
different problems with different fixes, and folding both into a generic API error
loses that.

Every provider maps its errors into this. That mapping is per-provider work — the
same condition arrives as different status codes and bodies from each — and it is
the most valuable thing in this phase.

### 030.010.015 — Feed the additions back to Ruby

`is_retryable` / `retry_after` have no Ruby equivalent, and neither do
`ContentFiltered` and `ContextLength`. Add all four to the gem
([080.020](080.000.000-phase-ruby-parity.md)) — a `retryable?` predicate on the
base error class, and two new subclasses.

Do this in the same cycle, not "later". The taxonomy is only worth anything if it
stays identical across languages.

### 030.010.020 — Extract `retry-policy` (layer 2)

Backoff computation, jitter, attempt limits, and attempt records are not
LLM-specific. Extract to a standalone crate per
[`../PLAN/005`](../PLAN/005.000.000-decomposition-principle.md); `cosmos-llm`
supplies the classification, the crate supplies the schedule.

```rust
pub struct RetryPolicy {
    pub max_attempts: u32,
    pub initial_backoff: Duration,
    pub max_backoff: Duration,
    pub multiplier: f64,
    pub jitter: Jitter,
}
```

### 030.010.030 — Honor `Retry-After`

When a 429 carries `Retry-After`, use it instead of computed backoff. Providers
know their own limits better than our exponential curve does, and ignoring the
header is how a client gets rate-limited harder.

Cap it — a `Retry-After: 3600` should fail rather than sleep for an hour.

### 030.010.040 — Jitter is not optional

Full jitter by default. Several concurrent requests hitting a rate limit and
retrying on identical schedules produce a synchronized thundering herd that
re-triggers the limit. The harness dispatches tools concurrently, so this is a real
case, not a distributed-systems fable.

### 030.010.050 — Retry is opt-in at the client

`Client::with_retry(policy)`. Default off, because a library that silently retries
surprises callers who are doing their own — and because a retry is a charge on
someone's account.

Document that the harness enables it.

### 030.010.060 — Attempt records

A failure after exhausting retries carries every attempt: when, what error, how
long the backoff was. This is what makes "why did this take 40 seconds" answerable.

## Verification

- Mock provider returning each error class; assert `is_retryable` per class.
- `Retry-After` honored, and capped at the configured maximum.
- Jitter produces distinct schedules across concurrent callers.
- Non-retryable errors fail on the first attempt with no delay.
- `retry-policy` tests run with an injected clock and no `cosmos-llm` dependency.
