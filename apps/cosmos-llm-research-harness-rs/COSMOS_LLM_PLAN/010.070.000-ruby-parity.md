# 010.070 — Toward Ruby parity

The Ruby client supports sixteen providers: anthropic, openai, azure_openai,
google, cohere, mistral, groq, fireworks, together, deepseek, openrouter,
perplexity, xai, huggingface, opencode. Rust will have five after
[010.050](010.050.000-google.md) and [010.060](010.060.000-ollama.md).

## Most of the gap is not real work

Count them honestly. Of the eleven remaining:

**OpenAI-compatible, no new provider needed** — groq, fireworks, together,
deepseek, xai, perplexity, and most huggingface endpoints all speak the OpenAI
chat-completions format. `Client::new_with_base_url("openai", key, url)` already
serves them.

What they need is not code but **registry entries**: a `ProviderEntry`
([010.020](010.020.000-provider-registry.md)) per service with the right name,
`env_keys`, and `default_base_url`, whose `make` constructs the OpenAI provider
pointed at that URL. Seven providers, one small file, no new wire-format code.

That is the payoff of doing the registry before the providers.

**Genuinely different wire formats** — cohere (its own chat API with a distinct
`chat_history` shape), mistral (close to OpenAI but with divergences worth
handling), azure_openai (OpenAI format, but deployment-based URLs and a different
auth header).

**Special cases** — `opencode` is already handled by `config::load_opencode_auth`,
which reads credentials from an existing opencode login rather than being a
provider.

## Microsteps

### 010.070.010 — The compatible-provider entries

Seven `ProviderEntry` registrations with correct metadata. Verify each against its
service — "OpenAI-compatible" is a claim vendors make with varying rigor, and the
divergences are usually in streaming or tool calls, not basic completion.

Test each against recorded fixtures from the real service. A vendor that diverges
gets promoted to a real provider implementation.

### 010.070.020 — Azure OpenAI

URLs are `{endpoint}/openai/deployments/{deployment}/chat/completions?api-version=…`
and auth is `api-key`, not `Authorization: Bearer`. The model name is a deployment
name chosen by the customer, so `models()` cannot enumerate meaningfully.

Enough divergence to justify its own provider despite the shared body format.

### 010.070.030 — Cohere

Its own API shape. A real implementation. Lower priority unless someone asks —
Cohere's usage among the likely users of this stack is low.

### 010.070.040 — Mistral

Close to OpenAI. Try the compatible route first with fixtures from the real API; if
it holds, it is a registry entry. If tool calls or streaming diverge, promote it.

### 010.070.050 — Do not chase the number

Sixteen is a number, not a goal. Each provider is a maintenance commitment: a wire
format that changes, fixtures that go stale, an error taxonomy to keep current.

Add providers people use. The registry means a user can add their own without
waiting for us, which is the better answer for the long tail.

## Verification

- Each compatible-provider entry passes the shared OpenAI-format test suite against
  its own recorded fixtures.
- Azure resolves deployment-based URLs correctly.
- `provider list` shows every registered provider with its description.
