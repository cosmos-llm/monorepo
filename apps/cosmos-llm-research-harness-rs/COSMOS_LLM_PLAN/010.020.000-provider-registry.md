# 010.020 — Registry-based provider resolution

## Current state

`providers::resolve_with_base_url` is a `match` over three lowercase names. Adding
a provider means editing that function, the module list, and any config
enumeration — three files for one addition.

## Microsteps

### 010.020.010 — `ProviderEntry`

Per [`../PLAN/005.010`](../PLAN/005.010.000-plugin-registry-pattern.md):

```rust
pub struct ProviderEntry {
    /// Canonical name, lowercase. Matched case-insensitively.
    pub name: &'static str,
    /// Alternate names accepted for this provider.
    pub aliases: &'static [&'static str],
    /// Human-readable description for `provider list`.
    pub description: &'static str,
    /// Environment variables checked for an API key, in order.
    pub env_keys: &'static [&'static str],
    /// Default API root.
    pub default_base_url: &'static str,
    /// Higher wins on name collision. Built-ins are 0.
    pub priority: i32,
    /// Constructs the provider.
    pub make: fn(ProviderInit) -> Result<Box<dyn Provider>, CosmosError>,
}

durable_inventory::collect!(ProviderEntry);
```

`env_keys` as data removes the per-provider environment-variable logic currently
spread across `Config` — the `OPENAI_API_KEY` / `CLLM__OPENAI__API_KEY` pairs
become entries in the table.

### 010.020.020 — `resolve` reads the registry

`resolve_with_base_url` keeps its signature and becomes a registry lookup. No
caller changes. The `match` disappears.

### 010.020.030 — Discovery APIs

`providers::list()` and `providers::find(name)`. These are what let a CLI print
available providers, and what let config validation report "unknown provider 'opeani',
did you mean 'openai'?" — a suggestion the current code cannot make.

### 010.020.040 — Third-party providers

The payoff. A user's private provider crate submits a `ProviderEntry` and is
resolvable by name with no change to `cosmos-llm`. Overriding a built-in is a
higher `priority`.

Document the override in `provider list --verbose`, showing shadowed entries.
Silent shadowing is a debugging trap.

### 010.020.050 — The linking caveat

A provider crate that is linked but never referenced can be dropped by the linker
along with its registrations. Ship the mitigations from
[`../PLAN/005.010`](../PLAN/005.010.000-plugin-registry-pattern.md): a public
`init()` shim, a debug-build assertion that built-ins are present, and a
`provider list` that makes the problem visible.

## Verification

- All three built-ins resolve by name and by alias after conversion.
- A test-submitted entry at high priority shadows a built-in; `list` shows both.
- Unknown name produces a suggestion from the registered set.
- Debug assertion fires if a built-in is missing.
