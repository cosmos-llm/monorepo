# 020.010 — Async executor

**Critical path.** Every research tool is I/O-bound.

## Current state

```rust
pub struct Executor;
impl Executor {
    pub fn execute(tool: &ToolDefinition, params: &Value) -> Result<Value, ToolError>;
}
```

`ToolDefinition` holds a synchronous handler. The `webfetch` preset is feature-gated
on `tokio` precisely because it needs to do something the signature does not allow.

## Microsteps

### 020.010.010 — Async handler variant

Do not replace the sync handler — many tools are genuinely synchronous (parsing,
arithmetic, string work) and forcing them into futures adds allocation and
complexity for nothing.

Support both:

```rust
pub enum Handler {
    Sync(Arc<dyn Fn(&Value) -> Result<Value, ToolError> + Send + Sync>),
    Async(Arc<dyn Fn(Value) -> BoxFuture<'static, Result<Value, ToolError>> + Send + Sync>),
}
```

`Executor::execute` stays for sync-only tools. `Executor::execute_async` handles
both — awaiting async handlers, calling sync ones inline.

### 020.010.020 — Feature-gate the async half

`async` feature, default on. Consumers who only use sync tools should not pull in
`futures`. Keep `cosmos-llm-tool` usable in a non-async context; that is part of
what makes it independently valuable.

### 020.010.030 — Timeouts belong here

`ToolDefinition` gains an optional timeout. `execute_async` enforces it. A tool
that hangs must not hang the agent loop, and every caller writing its own timeout
wrapper is duplicated logic that will be inconsistent.

### 020.010.040 — Cancellation

Handlers receive a context carrying a cancellation signal, or rely on drop
semantics. Drop is simpler and works for `reqwest`-based tools; document which
guarantee handlers can rely on, because "it probably gets cancelled" is not a
guarantee anyone can build on.

### 020.010.050 — Fix `webfetch`

Once async handlers exist, `webfetch` becomes a normal async tool and stops
needing its runtime workaround. That is the proof the design is right.

### 020.010.060 — Concurrent execution helper

`Executor::execute_all(calls) -> Vec<Result<Value, ToolError>>` running independent
calls concurrently with a bounded semaphore. The harness needs this
([`../PLAN/030.030.020`](../PLAN/030.030.000-agent-loop.md)) and so will every
other agentic consumer — it should not be reimplemented per application.

## Ruby note

Ruby's story differs: threads, not futures. The gem port should keep the *shape*
(a tool has a handler, an executor runs it, timeouts and concurrency are the
executor's job) and express concurrency idiomatically. Do not try to port
`BoxFuture` into Ruby.

## Verification

- Sync and async tools coexist in one registry and one execution batch.
- A tool exceeding its timeout returns a timeout error and does not block others.
- `execute_all` respects the concurrency bound.
- `webfetch` works without constructing its own runtime.
- The crate compiles and its sync tests pass with `--no-default-features`.
