# 040.030 — `llm-token-estimate` (layer 2)

A standalone crate. Nothing about counting tokens for a model family requires
Cosmos-LLM, and plenty of people outside this project need it.

## Microsteps

### 040.030.010 — Two tiers of accuracy

**Exact**, where a tokenizer exists: `tiktoken-rs` for OpenAI models (cl100k,
o200k). Anthropic does not publish its tokenizer, so exactness is not available
there regardless of effort.

**Estimated**, otherwise: characters-per-token ratios calibrated per model family,
with a stated error margin.

The API must not blur these. `TokenCount::Exact(n)` versus
`TokenCount::Estimated { n, margin }`. A caller budgeting against an estimate needs
to know to leave headroom.

### 040.030.020 — Feature-gate the tokenizers

`tiktoken-rs` pulls in vocabulary data and is not small. Behind a feature, default
off, so a consumer wanting only estimates does not carry megabytes of vocabulary.

The crate must be useful and lightweight with `--no-default-features`.

### 040.030.030 — Message overhead

Token count is not the sum of message contents. Each message carries role tokens
and formatting overhead, and providers differ in how much. Tool definitions add
their schema, which is often larger than people expect.

Model this per provider family. Undercounting here is why "it fit in my estimate"
requests get rejected.

### 040.030.040 — Calibrate against reality

Build a fixture set of prompts, send them to real APIs once, record the reported
usage, and calibrate the estimators against those numbers. Store the fixtures; the
calibration test runs offline against them.

An estimator nobody checked against a real API is a guess with a confident type
signature.

### 040.030.050 — Budget arithmetic

`TokenBudget` — capacity, reservation, remaining, and saturating subtraction. Used
by [040.020](040.020.000-budget.md) and by the harness. Small, but it belongs with
the counting rather than being reinvented next to it.

## Verification

- Exact counts match `tiktoken` reference vectors for OpenAI models.
- Estimates fall within their stated margin across the calibration fixtures.
- Message overhead matches recorded real usage within the margin.
- `--no-default-features` builds and passes its tests.
- No dependency on any `cosmos-llm` crate.
