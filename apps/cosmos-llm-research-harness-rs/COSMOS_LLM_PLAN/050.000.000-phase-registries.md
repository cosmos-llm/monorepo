# Phase 050 — Registries across the ecosystem

Convert dispatch from `match` statements and manual registration to
`durable-inventory` registries across all four Cosmos-LLM crates, per
[`../PLAN/005.010`](../PLAN/005.010.000-plugin-registry-pattern.md).

**Exit criteria:** a third party can add a provider, a tool, or a renderer from
their own crate with no change to Cosmos-LLM, and shadowing is visible.

## Steps

Most of the work is specified in the phases that introduce each registry:

- [010.020](010.020.000-provider-registry.md) — `ProviderEntry`
- [020.030](020.030.000-tool-registry.md) — `ToolEntry`
- [040.010.020](040.010.000-renderer-parity.md) — `RendererEntry`

What remains here is the cross-cutting work.

## 050.010 — Shared registry infrastructure

The five registries share: name matching (case-insensitive, alias-aware), priority
resolution, listing, and the "did you mean" suggestion on a miss.

Write it once. A small `cosmos-llm-registry` crate, or a macro, so a sixth registry
is a declaration rather than a hundred lines of copied lookup code.

Suggestion quality matters more than it sounds — `provider 'opeani' not found; did
you mean 'openai'?` versus `unknown provider` is the difference between a
five-second fix and a documentation search.

## 050.020 — Diagnostics

A `registries()` introspection API returning every registry, its entries, each
entry's source crate, and which entries are shadowed.

The harness exposes this as `cllm-research plugins`
([`../PLAN/050.010.020`](../PLAN/050.010.000-cli-surface.md)). It is the first
diagnostic for "my plugin is not loading", which is the failure mode this pattern
introduces.

## 050.030 — The linker problem, handled once

A crate linked but never referenced can have its registrations stripped. Handle it
consistently across all five registries:

1. Every registry-contributing crate exposes an empty `pub fn init()`.
2. Debug builds assert each registry contains its expected built-ins, panicking
   with the missing name.
3. Documentation states the symptom and the fix in one place.

Do this once, in the shared infrastructure, rather than five times inconsistently.

## 050.040 — Ruby equivalent

Ruby has no link sections and does not need them. `Class#inherited` plus explicit
`register` in a base class, with Zeitwerk handling autoload, gives the same
declare-locally-discover-centrally property.

Keep the *concept* and the entry metadata across languages — `find(name)`,
`list()`, priority override. Drop the mechanism. A developer moving between the
Ruby gem and the Rust crate should recognize the API even though the implementation
has nothing in common.

## Verification

- Third-party entries in every registry, added from a test crate.
- Shadowing visible in every registry's listing.
- Debug assertion fires on a stripped built-in.
- Suggestions produced for near-miss names.
