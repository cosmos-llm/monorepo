# 010.050 — Google (Gemini) provider

First real provider after the mock. The old TypeScript had one; the Ruby client has
one; Rust does not.

## Microsteps

### 010.050.010 — Wire format

Gemini's API is neither OpenAI- nor Anthropic-shaped. Notable differences to handle
in translation:

- Messages are `contents` with `parts`, and roles are `user` / `model` — no
  `assistant`.
- System instructions go in a separate `systemInstruction` field, not the message
  list. Report `SystemMessageSupport::Native` and translate.
- Tools are `functionDeclarations` under a `tools` array with its own schema
  dialect (a subset of OpenAPI, not JSON Schema — some keywords are rejected).
- Generation parameters live under `generationConfig`, not at the top level.

The tool schema difference is the sharp edge. A JSON Schema that works with OpenAI
may be rejected by Gemini. Translate and validate, and fail with a clear message
rather than passing through an unsupported keyword.

### 010.050.020 — Streaming

`streamGenerateContent` with `alt=sse`. Reuse `stream_from_response` with a
Gemini-specific `parse` closure, as anthropic does.

Gemini's chunks carry cumulative candidates in some modes rather than deltas.
Verify against real responses and normalize to deltas, since `StreamChunk` is a
delta type and a cumulative chunk fed to `StreamAccumulator` would duplicate text.

### 010.050.030 — Models

`GET /v1beta/models`. Returns richer metadata than most — input/output token limits
and supported methods per model — which feeds `ModelInfo`
([010.010.040](010.010.000-trait-review.md)) nicely.

### 010.050.040 — Environment and auth

`GOOGLE_API_KEY` / `CLLM__GOOGLE__API_KEY`, plus `GEMINI_API_KEY` as an alias since
that is what Google's own docs use. Key goes in a header or a query parameter
depending on endpoint — use the header, and make sure it never lands in a logged
URL.

Vertex AI (service-account auth, regional endpoints) is a different auth model.
Out of scope here; a separate `google-vertex` provider later if wanted.

### 010.050.050 — Safety settings

Gemini applies content filters by default and returns a blocked response with a
`finishReason` of `SAFETY` rather than content. Surface this as a distinct error
variant, not as an empty completion — a consumer that gets `""` back has no way to
know why.

## Verification

- `mockito` tests against recorded fixtures for completion, streaming, tools, and
  models.
- A blocked-by-safety response produces the distinct error.
- Tool schema translation rejects unsupported keywords with a clear message.
- Streaming reconstructs to the same response as non-streaming.
