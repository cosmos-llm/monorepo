# Cosmos-LLM Rust — Extension Plan

Work needed in the Cosmos-LLM crates (and the generic crates beneath them) so the
research harness can be built as a thin shell rather than a monolith.

This is the companion to [`../PLAN/`](../PLAN/000.000.000-index.md).

## Numbering

Same as `PLAN/`: `PHASE.STEP.MICROSTEP`, three digits each, counting by tens.

## The governing goal

**As much as possible belongs in Cosmos-LLM, not in the harness.** Rust crates
first, then Ruby gems, then the other clients. A capability that lands here serves
every consumer in every language; the same capability written into the harness
serves one binary.

Applied concretely: when planning a feature for the harness, the first question is
which layer owns it. If the answer is anything below layer 5, it belongs in this
plan, not that one.

## Current state

Four crates in `lib/rust/`, all at 0.1.0. The five critical-path items below have
landed; the gaps column is what remains.

| Crate | What it has | Main gaps |
|---|---|---|
| `cosmos-llm` | Client, config, 3 providers (openai, anthropic, openrouter), streaming with `StreamAccumulator`, SSE decoder, opencode auth loading, **mock provider**, **tool-result messages with per-provider serialization**, **Ruby error taxonomy with `is_retryable`/`retry_after`**, **opt-in `Client::with_retry`** | No fallback, no embeddings, no usage/cost, no fluent client builders |
| `retry-policy` (layer 2) | Exponential backoff, `Jitter`, `Retryable` classification seam, `Retry-After` honoring with a cap, attempt records, injected clock and randomness | Adequate |
| `cosmos-llm-tool` | `ToolDefinition`, `Registry`, `Parameter`, presets (read/write/glob/grep/list/webfetch), **async executor with timeouts and bounded `execute_all`** | No registry-based discovery. Missing presets: `diff`, `patch`, `exec`, `jq`. |
| `cosmos-llm-context` | `ContextBuilder`, `Block`, `RenderFormat`, virtual filesystem attachment | Renderer set needs verifying against Ruby's five; no token budgeting |
| `cosmos-llm-virtual-filesystem` | In-memory tree | Adequate |

The Ruby client supports 16 providers. The Rust client supports 3. That gap is the
single largest item here.

Beyond providers, Ruby is ahead in ways that change the work: it already has an
agent loop (`Tool::Loop`), a twelve-class error hierarchy, response helpers with
cost estimation, six more tool presets, and nine fluent client builders Rust lacks.
See [005](005.000.000-ruby-parity-principle.md) for the full audit and what each
one changes.

## Critical path for the harness MVP

Ordered by what blocks what. Items 1–4 have landed; 5 is next.

1. **[010.040](010.040.000-mock-provider.md) — mock provider. Done.**
   `providers::mock::MockProvider` behind the default-on `mock` feature: scripted
   responses, failure injection, request capture, canned modes, configurable
   chunking, and streaming that reconstructs the non-streaming response exactly.
   `Client::from_provider` was added so it works wherever a real provider does.
2. **[020.020](020.020.000-tool-messages.md) — tool-result messages. Done.**
   `Message` gained `tool_call_id`, `tool_calls`, and `name`, with
   `Message::tool_result`, `tool_result_json`, `assistant_with_tools`, and
   `CompletionResponse::to_assistant_message`. Each provider translates them to
   its own wire shape — OpenAI's `"tool"` role, Anthropic's merged `tool_result`
   blocks — and a result with no id fails locally with a message naming the fix.
3. **[020.010](020.010.000-async-executor.md) — async executor. Done.**
   `Handler::{Sync,Async}` behind a default-on `async` feature,
   `Executor::execute_async` with per-tool timeouts, and `execute_all` with a
   bounded semaphore and order-preserving results. `webfetch` is a real async
   tool now; its `block_in_place` workaround is gone. The crate still builds and
   passes its sync tests with `--no-default-features`.
4. **[030.010.010](030.010.000-retry.md) — error classification. Done.**
   `CosmosError` now mirrors Ruby's taxonomy as struct variants carrying
   `provider` (`SYSTEM` where there is none), plus `is_retryable()`,
   `retry_after()`, and `provider()`. Shared `map_openai_error` /
   `map_anthropic_error` read the body's `type`/`code`, so an
   `insufficient_quota` 429 is correctly non-retryable and a mid-stream
   `overloaded_error` is correctly retryable.

   **Still open in 030.010:** feeding `retryable?`/`ContentFiltered`/
   `ContextLength` back to Ruby (030.010.015).
5. **[030.010.020–060](030.010.000-retry.md) — `retry-policy` crate. Done.**
   New layer-2 crate at `lib/rust/retry-policy`, zero dependencies without its
   default `tokio` feature. `RetryPolicy` with exponential backoff, `Jitter`
   (full by default), `Retryable` as the caller-implemented classification seam,
   and `RetryError` carrying every attempt with its delay and whether that delay
   was requested rather than computed.

   `Retry-After` is honored unjittered and capped by `max_retry_after`, so a
   `Retry-After: 3600` stops the loop instead of hanging for an hour.
   `Client::with_retry` is opt-in and off by default; it covers `completion` and
   `complete`, and deliberately not the streaming methods.

   Clock and randomness are both injected — the crate's own suite never touches
   a real clock, so it describes minute-long schedules in milliseconds.
6. **[030.020](030.020.000-fallback.md) — fallback chains.** Next.

Items 1–3 were the hard blockers on `PLAN` phase 030; that phase is now unblocked.

## Rules

1. **Open the Ruby equivalent before designing anything.** If one exists, port it.
   `grep -rn "def " lib/ruby/cosmos-llm-ruby-*/lib` is the first step of any new
   public API ([005](005.000.000-ruby-parity-principle.md)).
2. **No harness-shaped APIs.** If a proposed addition only makes sense to a research
   tool, it belongs in `cosmos-llm-research` (layer 4), not in `cosmos-llm`.
3. **Every crate stays independently useful.** The test in
   [`../PLAN/005`](../PLAN/005.000.000-decomposition-principle.md): can you write
   the README without saying "for use with"?
4. **Wire-format tests, not live tests.** `mockito` against recorded fixtures.
   `cargo test` must pass with no network and no API key.
5. **`#[non_exhaustive]` on every public enum.** These crates are meant to be
   depended on; adding a variant must not be a breaking change.
