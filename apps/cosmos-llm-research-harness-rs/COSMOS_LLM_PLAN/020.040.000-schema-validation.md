# 020.040 — Argument validation and repair

Models produce malformed tool arguments regularly: a string where a number belongs,
a missing required field, an enum value that is close but wrong. Handling this well
is the difference between a loop that recovers and one that fails.

## Microsteps

### 020.040.010 — Validate before executing

`Parameter` and `schemas` exist in `cosmos-llm-tool`. Confirm arguments are
validated against the declared schema *before* the handler runs, and that the
handler can rely on well-formed input.

A handler doing its own defensive parsing means the same checks written N times,
inconsistently.

### 020.040.020 — Errors the model can act on

A validation failure returns to the model as a tool result. It should say what was
wrong and what was expected:

```
invalid arguments for web_search:
  - "max_results": expected integer, got string "ten"
  - missing required field "query"
expected schema: {...}
```

Not `ToolError::InvalidParams`. The model reads this and retries correctly; a
generic error and it retries identically.

### 020.040.030 — Extract the generic half

This is `json-schema-coerce` (layer 2 in
[`../PLAN/005`](../PLAN/005.000.000-decomposition-principle.md)): validate a value
against a JSON Schema and produce human- and model-readable repair instructions.

Nothing about it is LLM-specific — a form validator or an API gateway wants the
same thing. Extract it and depend on it.

### 020.040.040 — Safe coercion

Some fixes are unambiguous and worth applying automatically: `"10"` where an
integer is required, `"true"` for a boolean, a single value where an array of one
is expected.

Coerce those and note it. Do not coerce ambiguously — a string where an object is
expected has no safe interpretation, and guessing produces a plausible wrong answer.
Coercion must be conservative or it is worse than rejection.

### 020.040.050 — Structured-output validation

The harness's `extract_structured`
([`../PLAN/030.040.050`](../PLAN/030.040.000-tools.md)) needs the same machinery for
a different purpose: validating a model's structured *output* against a schema, and
feeding violations back for one retry.

Same crate, same error formatting. Build it once.

## Verification

- Invalid arguments produce messages naming each problem field and its expectation.
- Safe coercions apply; ambiguous ones reject.
- A mock-provider loop test: bad arguments → error → model retries → succeeds.
- `json-schema-coerce` tests run with no dependency on `cosmos-llm-tool`.
