# Phase 080 — Porting back to Ruby, and beyond

Parity runs both directions. [005](005.000.000-ruby-parity-principle.md) covers
what Rust takes *from* Ruby — the agent loop, the error taxonomy, the response
helpers, the missing presets. This phase covers the reverse: what Ruby should take
from the work done here, and what must stay identical across both.

**Exit criteria:** the Ruby gems gain the capabilities this plan adds to Rust, with
APIs a Ruby developer would have written.

## What to port back, in priority order

### 080.010 — Agent loop extensions

Ruby has `Cosmos::Llm::Tool::Loop` already. What it lacks is what
[070.010](070.010.000-agent-crate.md) adds in Rust:

- **Cancellation** — Ruby has no equivalent today.
- **Event emission** — progress, tool start/finish, usage.
- **Permission dispatch** — the capability model and its single choke point.
- **Concurrent tool dispatch** — a thread pool, not a semaphore over futures.
- **Non-Anthropic providers** — the loop currently builds Anthropic content-block
  messages and documents that other providers are unsupported. Fix in both.

The *shape* stays identical; the mechanism differs by language.

Whether these land in the existing `cosmos-llm-tool` gem or a new
`cosmos-llm-agent` gem is a Ruby-side structural call. The Rust split exists
because the loop has a wider audience than research does; the same argument applies
to Ruby, but the loop already lives in the tool gem and moving it is a breaking
change. Decide when scheduling, not now.

### 080.020 — Resilience

Retry, backoff, and fallback ([030](030.000.000-phase-resilience.md)). Ruby has
none of these.

The error *taxonomy* needs no porting — Rust adopts Ruby's twelve classes
([030.010.010](030.010.000-retry.md)). What Ruby needs back is four additions:

- `retryable?` and `retry_after` on the base error class.
- `ContentFilteredError` and `ContextLengthError` as new subclasses.

Do these in the same cycle as the Rust work. A taxonomy that matches in eleven of
fifteen places is not a taxonomy that matches.

### 080.025 — Streaming accumulator

Rust's `StreamAccumulator` rebuilds a complete response from chunks, including
assembled tool calls and usage. Ruby has no equivalent, which means a streaming
tool loop is not currently expressible there.

Port it. This is the clearest case of Rust leading.

### 080.026 — Base-URL override

Rust's `Client.new_with_base_url` covers every OpenAI-compatible endpoint with one
provider implementation. Ruby has a separate class per vendor, several of which are
the OpenAI format with a different URL.

A base-URL override would collapse those and make the long tail
([010.070](010.070.000-ruby-parity.md)) a registration rather than a class.

### 080.027 — Fix the `DLLM__` leftovers

`providers/base.rb:254` and three sites in `cli.rb` still emit `DLLM__`, while
`configuration.rb` documents and loads `CLLM__`. Users following the CLI's advice
set a variable the loader ignores.

Fix the strings; accept `DLLM__` as a deprecated alias with a warning. Small, and
currently a live bug.

### 080.030 — Registries

Per [050.040](050.000.000-phase-registries.md): keep the concept, drop the
mechanism. `Class#inherited` plus explicit registration in a base class, with
Zeitwerk handling autoload. `find(name)`, `list`, priority override.

### 080.040 — `cosmos-llm-research` gem

The vertical. Lower priority than the agent gem, because it serves one use case
rather than all of them.

### 080.050 — The generic layer-1 crates

`citation`, `citation-style`, `bibtex-io` have obvious Ruby equivalents worth
having. Others (`sse-decode`, `jsonl-log`) have mature Ruby gems already —
check before writing. Porting a solved problem to compete with an established gem
helps nobody.

## What must stay consistent

[005](005.000.000-ruby-parity-principle.md) is the authority — it lists what must
match and what may differ. The one item needing enforcement machinery here:

**Prompt rendering.** A context rendered by the Ruby and Rust renderers must
produce identical output. Cross-language golden files
([040.010.010](040.010.000-renderer-parity.md)) enforce it, and they are the only
consistency requirement in this plan that can be checked automatically.

Build the fixture set once and run it from both test suites. Divergence here means
the same application gets different model behavior depending on which client it
uses, which is nearly impossible to diagnose from the outside.

## Other languages

JavaScript/TypeScript and Crystal clients exist in `lib/`. Same principles apply,
same priority order. The agent loop first, because it is what is missing everywhere.
